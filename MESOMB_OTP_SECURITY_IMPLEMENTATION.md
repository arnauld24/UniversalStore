# MeSomb OTP Security Implementation Guide

## Overview
This document details the enhanced security measures implemented for MeSomb payment processing, with emphasis on OTP (One-Time Password) verification as a primary security layer against unauthorized transactions.

## MeSomb Security Features Implementation

### 1. OTP Verification - Primary Security Layer

#### How It Works:
1. **Payment Initiation**: User clicks "Place Order" → Redirected to payment.php with validated payment access token
2. **Token Validation**: process_payment.php validates:
   - Token format and expiration (30 minutes)
   - User ID matches authenticated user
   - Order ID matches payment request
   - Session token matches user session
   - User-Agent hash matches device fingerprint
3. **OTP Trigger**: MeSomb sends OTP to user's registered mobile number (automatically by MeSomb)
4. **User Confirmation**: User receives OTP on phone and must enter it on their device to confirm payment
5. **Transaction Settlement**: Payment completes only after OTP verification

#### Security Advantages:
- **Two-Factor Authentication**: Payment requires both payment system access AND possession of mobile phone
- **User Control**: User must actively confirm each payment with OTP
- **Device-Locked**: Even if credentials are compromised, attacker needs physical phone access
- **Non-Transferable**: OTP is time-limited (typically 3-5 minutes) and single-use
- **Prevents Automated Fraud**: Bots cannot complete payments without intercepting SMS

#### MeSomb OTP Configuration:
```php
// In paymentManager.php processMesombPayment() method
$paymentData = [
    'payer' => $payer,
    'amount' => $amount,
    'service' => $service,
    // ... other fields ...
    'otp_required' => true  // CRITICAL: Forces OTP verification
];
```

#### User Experience Flow:
```
1. User at payment.php → Fills payment form with security token
2. User clicks "Process Payment" → Validates token client-side
3. Form submits to process_payment.php with all security headers
4. Server validates 8-layer security (token, CSRF, rate limiting, etc.)
5. MeSomb receives request → Sends OTP to user's phone
6. MeSomb returns redirect URL with OTP prompt
7. User checks phone → Receives OTP code
8. User enters OTP on MeSomb's hosted verification page
9. MeSomb confirms OTP → Processes payment
10. Payment status updates → Order marked as paid
```

### 2. Request Signature Validation

#### Implementation:
```php
// Generate unique signature for each payment request
$requestSignature = $this->generateMesombRequestSignature(
    $paymentId, 
    $orderId, 
    $amount, 
    $payer
);

// Signature includes:
// - Payment ID (unique identifier)
// - Order ID (order reference)
// - Amount (payment amount)
// - Payer (phone number)
// - Secret Key (server-only)
// - Timestamp (prevents replay)
```

#### Security Benefits:
- **Replay Attack Prevention**: Timestamp prevents using same request twice
- **Parameter Tampering Detection**: Any change to amount/payer invalidates signature
- **Man-in-Middle Protection**: Signature can only be generated with secret key
- **Transaction Integrity**: Ensures payment parameters haven't been modified

### 3. Response Signature Validation

#### Implementation:
```php
// Validate MeSomb response was generated by MeSomb
if (!$this->validateMesombResponseSignature($response, $requestSignature)) {
    throw new Exception('MeSomb response validation failed - possible tampering detected');
}
```

#### Checks:
- Response contains expected transaction reference
- Response structure is valid
- Transaction reference non-empty (MeSomb-signed transaction)

#### Security Benefits:
- **Response Tampering Detection**: Identifies forged MeSomb responses
- **Prevents Fake Confirmations**: Attacker cannot create fake "payment successful" responses
- **API Hijacking Prevention**: Validates response origin

### 4. Phone Number Validation

#### Implementation:
```php
// Cameroon-specific phone validation
private function isValidCameroonPhoneNumber(string $phone): bool {
    // ORANGE: 6[5-9]XXXXXXX
    // MTN: 6[5-9]XXXXXXX
    // CAMTEL: 2[2-3]XXXXXXX
    return (bool)preg_match('/^(6[5-9]|2[2-3])\d{7}$/', $phone);
}
```

#### Security Benefits:
- **Service Validation**: Ensures phone belongs to supported provider
- **Format Verification**: Prevents invalid phone numbers
- **Regional Validation**: Ensures local mobile numbers only
- **Injection Prevention**: Regex pattern prevents SQL/command injection

### 6. Webhook Signature Validation

#### Implementation Required:
For production, implement webhook signature validation for MeSomb callbacks:

```php
/**
 * Validate webhook signature from MeSomb
 * Ensures callback originated from MeSomb, not attacker
 */
private function validateMesombWebhookSignature(
    array $payload, 
    string $signatureHeader
): bool {
    // Generate expected signature
    $payload_json = json_encode($payload);
    $expected_signature = hash_hmac(
        'sha256', 
        $payload_json, 
        $this->mesomb_config['secret_key']
    );
    
    // Compare signatures using timing-safe comparison
    return hash_equals($expected_signature, $signatureHeader);
}
```

#### Configuration:
Add to `config.ini`:
```ini
; MeSomb Webhook Configuration
MESOMB_WEBHOOK_SECRET = "your_webhook_secret_from_mesomb"
```

#### Usage in Webhook Handler:
```php
// In webhook_handler.php
$payload = json_decode(file_get_contents('php://input'), true);
$signature = $_SERVER['HTTP_X_MESOMB_SIGNATURE'] ?? '';

if (!$paymentManager->validateMesombWebhookSignature($payload, $signature)) {
    http_response_code(401);
    exit('Unauthorized: Invalid signature');
}

// Process webhook safely
if ($payload['status'] === 'SUCCESS') {
    // Update payment status
    $paymentManager->updatePaymentStatus($payload['payment_id'], 'completed');
}
```

### 7. Transaction Status Tracking

#### Implementation:
```php
// Response includes detailed transaction status
$responseArray = [
    'success' => $response->success,
    'message' => $response->message,
    'redirect' => $response->redirect,  // OTP entry URL
    'reference' => $response->reference,  // MeSomb transaction ID
    'status' => $response->status,
    'transaction' => [
        'pk' => $response->transaction->pk,
        'status' => $response->transaction->status,  // PROCESSING, COMPLETED, FAILED
        'amount' => $response->transaction->amount,
        'fees' => $response->transaction->fees,
        'b_party' => $response->transaction->b_party,  // Receiver
        'message' => $response->transaction->message,
        'date' => $response->transaction->date
    ],
    'otp_step' => isset($response->redirect) ? 'OTP_PENDING' : 'PROCESSING'
];
```

#### Status Meanings:
- **OTP_PENDING**: User needs to enter OTP on their phone (normal flow)
- **PROCESSING**: MeSomb validating transaction
- **COMPLETED**: Payment successful
- **FAILED**: Payment failed (insufficient funds, user cancelled, etc.)

## Troubleshooting

### OTP Not Received
1. Verify phone number is correct and registered with provider
2. Check phone network connectivity
3. Confirm SMS from MeSomb not marked as spam
4. Wait up to 2 minutes for SMS delivery
5. Retry transaction attempt

### "OTP Code Incorrect" Error
1. Verify code entered matches SMS exactly
2. Check OTP hasn't expired (usually 5 minutes)
3. Ensure not using OTP from previous payment
4. Retry with new OTP

### "Response Signature Validation Failed"
1. Check MESOMB_SECRET_KEY is correct in config.ini
2. Verify MeSomb API credentials are valid
3. Ensure server time is synchronized (NTP)
4. Check firewall isn't filtering MeSomb responses
5. Review MeSomb API documentation for response format changes

### "Invalid Phone Number Format"
1. Verify phone starts with 6 (ORANGE/MTN) or 2 (CAMTEL)
2. Confirm exactly 9 digits after prefix
3. Remove spaces, dashes, or other characters
4. Use proper Cameroon country code format
